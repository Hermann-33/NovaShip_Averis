### 1.4 Auth
- Built-in login (default, any backend): the browser signs in at `/login` (`POST /auth/login`) and sends the HMAC-signed session token as `Authorization: Bearer nsa....`. Passwords are PBKDF2 hashes in `user_credentials` (migration `0004_accounts.sql`); every seeded user gets `DEMO_PASSWORD` (`novaship123`) on first start. `POST /auth/register` creates least-privilege accounts, `POST /auth/logout` revokes the session (`revoked_sessions`). Users and roles still come from `users` / `user_roles`.
- Demo header: with `AUTH_MODE=demo`, `X-User-Id: <user id>` is also accepted for curl, scripts and tests. There is no default user any more: a request without credentials is 401.
- Supabase Auth (optional): add users (email + password or Google). Insert a `users` row with `id = auth.users.id` and `user_roles` rows. Set `AUTH_MODE=jwt` to disable the demo header; a Supabase JWT sent as `Authorization: Bearer` is verified with `SUPABASE_JWT_SECRET` alongside the built-in session tokens (`lib/api.ts` stores the session in `localStorage.novaship.session`). RLS uses `auth.uid()` and `app_metadata.roles`.

## Part 4, Deploy the backend with Cloudflare
Two options; both keep the API in the Docker image you already built.

**Option A, Cloudflare Tunnel in front of any host (fastest for the hackathon).** Run the API container on a VM or on your laptop, expose it with a tunnel, get a stable HTTPS URL.
```bash
# on the machine running docker compose up -d api
winget install Cloudflare.cloudflared   # or brew install cloudflared
cloudflared tunnel login                # opens the browser, pick your zone (or use a free trycloudflare URL below)
cloudflared tunnel create novaship-api
cloudflared tunnel route dns novaship-api api.yourdomain.com
cloudflared tunnel run --url http://localhost:8000 novaship-api
# no domain? quick tunnel (temporary URL, fine for a demo):
cloudflared tunnel --url http://localhost:8000      # prints https://xxxx.trycloudflare.com
```
Set `CORS_ORIGINS=https://<vercel-app>.vercel.app,http://localhost:3000` in `.env` and restart the API.

**Option B, Cloudflare Containers (Workers platform, container runs in Cloudflare).**
```bash
npm i -g wrangler && wrangler login
# wrangler.toml at repo root
#   name = "novaship-api"
#   [[containers]]  image = "./backend/Dockerfile"  name = "api"  instance_type = "standard"
#   [vars] REPO_BACKEND="supabase"  AUTH_MODE="demo"
wrangler secret put SUPABASE_URL ; wrangler secret put SUPABASE_SERVICE_ROLE_KEY ; wrangler secret put OPENAI_API_KEY ; wrangler secret put GOOGLE_API_KEY
wrangler deploy
```
The Dockerfile build context is the repo root (it copies the bundle and seed), so run wrangler from the root. Cloudflare Containers is a paid Workers feature; if the account does not have it, use Option A.

Any other container host works the same (Fly.io `fly launch --dockerfile backend/Dockerfile`, Render, Railway, Cloud Run): the image only needs `PORT` and the `.env` values.

## If something is wrong
| Symptom | Look at | Fix |
|---|---|---|
| 401 everywhere | `AUTH_MODE`, headers | sign in at `/login` (token expired after `SESSION_TTL_HOURS`?); demo: `X-User-Id`; jwt: Bearer + `SUPABASE_JWT_SECRET` |
| PostgREST "column does not exist" | `supabase_repo.save_case` vs `0001_schema.sql` | add a migration `0004_*.sql` and the column in the row dict |
| Seed too large for the editor | `--push` or `--limit 100` | REST pushes in chunks of 500 |
| CORS error in the browser | `CORS_ORIGINS` | include the exact Vercel origin, redeploy API |
| Graph 401/403 | admin consent, wrong tenant | check permissions are **Application**, not Delegated |
| Tunnel URL changed | quick tunnels are temporary | use a named tunnel with a DNS route |
